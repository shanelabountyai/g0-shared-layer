# Decisions — G0 Shared Capability Layer

One entry per decision, newest last. Owner = Shane. Dates are when decided, not when recorded. D-1 to D-10 were made by the owner before the G0·C run; D-11 onward were taken by the unattended G0·C run (2026-11-05) under the kickoff rule "take the most reasonable reading and record it here".

| # | Date | Decision | Why |
|---|---|---|---|
| D-1 | 2026-11-02 | **Six capabilities**: `claims.registry`, `brand.policy`, `audience.consent`, `measurement`, `evaluation`, `observability`. Built once, called as tools. | The thesis of the track: agentic work scales through shared capabilities, not more agents. |
| D-2 | 2026-11-05 | Built **after G1 and before G2**. G2–G5 attach here instead of carrying their own rules. | G1 was built without the layer on purpose; its `docs/duplication-log.md` is the input that says what the layer must pull out. |
| D-3 | 2026-11-05 | The layer is a **single point of failure**, so it gets its own contract tests, health check and change control. A contract shape change means a **version bump, never a silent edit**. | 3 agents × 6 tools is 18 integrations and 3 copies of the rules; with the layer it is 9 and 1 copy. The price of that is one thing everything depends on. |
| D-4 | 2026-11-05 | **Build order inside G0: C first** (this run), then the owner builds B by hand in n8n from the published contracts, then M. The PRD's B→C→M recommendation is superseded. | The code version publishes the contracts; the n8n sub-workflows are built to them, not the other way round. |
| D-5 | 2026-11-05 | The layer lives in its **own public repo, `g0-shared-layer`**. G1·C and G2–G5 depend on it as a **pinned git dependency**; `~/Projects/agentic-track/shared` is a clone. | One place G2–G5 point at; a pin means a contract bump is an explicit upgrade in each consumer. |
| D-6 | 2026-11-05 | **Storage: SQLite, one file**, path from `G0_DB_PATH` with a sane default (`~/.g0-shared-layer/layer.sqlite`; `:memory:` for tests). | Registries, events and logs fit one file; no service to run. |
| D-7 | 2026-11-05 | **Brand-policy seed v1 = the `brand_voice` rule from G1's duplication log**, including its never-use phrase list. The owner's personal-brand skill may extend it later as a new policy version. | That rule was already carried verbatim by G1's Editor and Writer. |
| D-8 | 2026-11-05 | **Claims-registry seed = the "Verified stats — safe to use" rows** of the Stalled-Pilot evidence brief (`li-lead-gen-tools/docs/research/stalled-pilot-evidence-brief.md`), with their sources. Nothing else from that file. | Those are the only rows the brief marks safe; "use with caution" and "do not use" rows stay out. |
| D-9 | 2026-11-05 | **Consent: synthetic contacts only.** A fixture of ~20 obviously fake contacts (`example.com` addresses) with per-channel consent flags. No real contact data anywhere in this repo. | Demo data, and a rule every consumer inherits. |
| D-10 | 2026-11-02 | The shipped **A2 Marketing-Ops Agent migrates onto this layer** (G0·M), a later run. `opsagent` is not touched in this run. | Proves the layer on something already in use. |
| D-11 | 2026-11-05 | **Python MCP SDK: `mcp` 2.3.0** (PyPI `mcp`, "Model Context Protocol SDK", https://modelcontextprotocol.io). Found by inspecting the package installed in the run environment and its source: v2 renamed `FastMCP` to `mcp.server.mcpserver.MCPServer`; tools are registered with `MCPServer.tool()` / `add_tool()`; a Pydantic return type yields an `outputSchema` and `structuredContent`; an anticipated failure is `mcp.server.mcpserver.exceptions.ToolError` (→ `is_error=True`); stdio via `MCPServer.run("stdio")`; client via `mcp.client.Client` with `StdioServerParameters` / `stdio_client`. The SDK's own migration guide (`py.sdk.modelcontextprotocol.io/v2/migration/`) could not be fetched by the unattended run (URL permission not grantable); the installed source was read instead. Pinned `mcp>=2.3,<3`. | Kickoff rule: confirm the SDK name, version and API before writing server code, and record what was found. |
| D-12 | 2026-11-05 | **Tool names use underscores** (`claims_registry`, `brand_policy`, `audience_consent`, `measurement`, `evaluation`, `observability`, `health`); the capability ids keep their dots (`claims.registry`, …) and appear in every contract as `capability`. | Tool-name rules in MCP clients and the Anthropic API allow `[A-Za-z0-9_-]` only; a dot in a tool name is refused by some hosts. |
| D-13 | 2026-11-05 | **A contract file is what the MCP client sees.** `contracts/<capability>/v1.json` holds the tool's advertised `inputSchema` and `outputSchema`, generated from the Pydantic models by `python -m shared_layer.contracts export`. `tests/contracts/golden/` pins a byte-for-byte copy. Both must match the live models or the suite fails. | One source of truth (the models), one published artifact (the JSON), one lock (the golden). n8n (G0·B) is built from the JSON. |
| D-14 | 2026-11-05 | **Every input and output carries `version` ("1")**; the output also carries `ok` and, when `ok` is false, an `error` envelope `{code, message, field?, next?: {tool, why}}`. Errors travel **inside the output schema**, not as `is_error`, so a client that validates `structuredContent` (Claude's do) never rejects a refusal. Only an unknown tool or a malformed argument is a protocol-level `is_error`. | A1's finding (bookable-appointment-service, M-015): an error placed outside the output schema reaches the model as an exception, not as something it can recover from. |
| D-15 | 2026-11-05 | **claims.registry v1 is deterministic**: a claim is `supported` when its normalized numbers match a registry entry's numbers and the two share topic words, or when it contains a registry entry's key phrase; `unsupported` when it shares topic words with an entry but its numbers contradict that entry; `needs_source` when the registry says nothing about it. When free `text` is given, only sentences that carry a number are extracted as claims; a `claims` list is checked item by item. | No model call needed; a wrong number against a known stat is the failure the registry exists to catch. Sentences without numbers are not "claims" the registry can speak to. |
| D-16 | 2026-11-05 | **brand.policy v1 is a rule engine** over seeded rules of four kinds: `phrase` (never-use list, case-insensitive), `regex` (emoji), `max_words` and `max_sentences` (post angle: one sentence, ≤25 words, on channel `post_angle`). Judgment rules in the brand voice ("never hype", "never a pitch", "specific over general") are not enforced by the engine; they are criteria of the `post_angle_v1` rubric in `evaluation`. The full verbatim `brand_voice` text is stored with the policy as `policy.text`. | Enforce what can be enforced exactly; route judgment to the judge; keep the owner's text intact. |
| D-17 | 2026-11-05 | **audience.consent fails closed**: an unknown contact, an unknown channel, a contact without a flag for that channel, or a `do_not_contact` contact is `allowed: false` with a reason. Lookup by `contact_id` or `email` (case-insensitive). | A consent check that defaults to "yes" is not a consent check. |
| D-18 | 2026-11-05 | **observability keeps the run total**: every log row is per (run_id, agent, step) with model, tokens, cost and status; the output returns the running total for that `run_id` against the **$10 cap** (`G0_RUN_CAP_USD`, default 10) and `over_cap`. The caller decides what to do when `over_cap` is true; the layer never blocks a log write. | This is G1's `run_logging` rule pulled out of four prompts into one place. Blocking a log would hide the overrun. |
| D-19 | 2026-11-05 | **evaluation has a pluggable judge.** No `ANTHROPIC_API_KEY` was present in the run environment, so no live model call was made (cost of live calls this run: **$0.00**). Shipped: `DeterministicJudge` (one check per rubric criterion), `FixtureJudge` (replays `tests/fixtures/evaluation_fixture.json`, which is a **hand-written sample in the Claude judge's output shape, not a recorded live response**), and `ClaudeJudge` (Anthropic Messages API, structured JSON, tokens and cost logged per call, refuses past the cap). `judge: "auto"` picks Claude when a key is present, else deterministic. Model id defaults to `claude-sonnet-5-5` (`G0_JUDGE_MODEL`), prices carried from G1 D-8 (`claude-haiku-5-5` $0.10/$0.50, `claude-sonnet-5-5` $2/$10, `claude-opus-5-5` $4/$20 per MTok, cache dated 2026-10-06). **Anthropic's pricing page could not be fetched by the unattended run; the owner confirms model id and prices before the first live call** (NEXT.md). | Kickoff rule for the no-key case. The fixture is labelled for what it is. |
| D-20 | 2026-11-05 | **Python 3.12, `uv`, `pyproject.toml`**, src layout, package `shared_layer`, distribution `g0-shared-layer`, console script `g0-shared-layer` (runs the stdio server). Consumers pin: `g0-shared-layer @ git+https://github.com/shanelabountyai/g0-shared-layer@<tag>`. Seeds live inside the package (`shared_layer/seeds/*.json`) so a git install carries them. | Kickoff working rule; seeds outside the package would not survive `pip install git+…`. |
| D-21 | 2026-11-05 | **health is a tool and an uptime log.** `health` returns db path and writability, seed counts, contract versions, server version and uptime, and writes one row to `health_log` each call. | PRD: "health check and a simple uptime log, since every agent depends on it". |
| D-22 | 2026-11-05 | **Measurement and observability are append-only**; nothing in v1 deletes or updates a row. `measurement` stores `fields` as JSON and never requires a schema per event; the event name is the contract. | Logs that can be rewritten are not logs. Event schemas per event name are a v2 question. |
